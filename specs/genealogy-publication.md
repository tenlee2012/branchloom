# 族谱编印与 PDF 导出

状态：完整范围已实现，编印自动化与 macOS 样张验收已通过；四平台实机验收尚未全部完成，全仓库原有检查失败另列。日期：2026-09-20。具体证据见 [验证记录](genealogy-publication-verification.md)。

## 1. 目标与已确认范围

将有谱项目编排为可校对、打印、装订并长期保存的族谱。一次交付本规格中的完整能力，不将已确认能力拆成后续版本。

用户已确认：

- 同时提供现代横排谱册、传统中文谱册、世系挂图。
- 成品格式仅为 PDF，不提供 Word、SVG 或线上代印服务。
- macOS、Windows、Linux、Android 均可在本机生成和保存 PDF，离线可用。
- 传统谱册采用图传分节：世系图与人物传记分别编排，通过人物编号和页码互查；竖排、右侧装订。不包含图传同页模板。
- 照片与文字引用可选入册；已有 PDF 史料支持选择页面收入附录。
- 支持保存多套编印方案，资料更新后按原方案重新生成。
- 按一万名人物规模设计和验收，特别关注 Android 内存、取消操作及大文档分页。

## 2. 成品与内容

### 2.1 现代谱册

默认 A4 纵向、横排、左侧装订、黑白。章节包括封面、谱序、目录、世系图、人物传记、家族大事记、史料来源、史料附录、姓名索引。用户可启用、关闭和排序章节；目录与索引中的页码以最终分页为准。

封面可设置标题、副标题、编修者、版次、编修日期及项目中的封面图片。谱序是用户提供的文字，初始为空，不根据人物资料编造家族源流或故事。默认标题取项目名。版次与编修日期属于编印方案。

未填写的谱序、没有事件或来源的章节、没有选中附件的附录自动略过，目录与书签同步略过，不打印占位文字或空章节页。若全部所选章节均为空，提示调整内容。无图封面使用居中的横排标题或传统竖排题签；长标题及图片封面保持完整内容。

人物传记支持主姓名、其他姓名及姓名类型、状态、生卒时间与地点、生平、备注、亲属关系、职业履历、称谓、照片和引用。保留“约”“之前”“之后”“区间”等原始日期表达。未知日期、关系及世代明确显示未知，不推算为确定事实；在世且未记录死亡日期时省略卒年。各字段可选；备注默认不选。大事记按已记录日期起点排序，仅有上界时使用上界，无可比较日期的事件另列；正文保留原始日期表达并说明排序依据。关系、履历及称谓的日期标明起止含义。

### 2.2 传统谱册

图传分节，正文按列自上而下、列自右向左，右侧装订；使用清晰的宋体字形、双栏线及统一版心。横排数字、拉丁字符和竖排标点必须有明确排版规则并覆盖样张测试。姓名、关系类型和日期的业务含义与现代谱册完全相同，不因传统外观排除女性、收养、继亲、监护、多段伴侣关系或其他已记录关系。

世系图保持关系可辨识，以局部图和续接标记分节；长传记和照片在人物传记章节自然续页。跨页标记包含人物编号和目标页码。人物标题不得孤悬在页末，续页显示人物名和“续”。

短字段按人物汇成连续竖排正文，保留各引用片段的内部链接；能在单页容纳的短传记、事件、来源记录尽量整段保留，避免只剩标题或几项字段的续页。

### 2.3 世系挂图

选择全谱、指定分支、祖先或后代；指定起始人物和代数。支持单页大幅 PDF 和普通纸张分幅 PDF。单页实际纸张随版面扩展，不把一万人缩进一张 A4；若超出 PDF/渲染器安全尺寸，明确要求使用分幅，不静默缩小到不可读字号。

分幅保留可读字号、拼接编号、行列位置、重叠区和总览定位。图上保留关系类型图例；不同类型不能仅靠颜色区分。跨幅人物和关系有可追踪的接续标记。

普通人物框不在纸边截断。单框关系过多时分为带编号的续框；关系双方均保留编号和目标页码。跨幅或跨世代分节的关系采用双向引用，不在页边绘制无标识的断线。

## 3. 范围、顺序和资料完整性

- 数据范围独立于交互家谱画布，不受画布加载上限、折叠状态、搜索结果和代数上限限制。
- 选择整个项目、一个或多个根人物的分支、祖先或后代。可设置代数、是否包含配偶、允许的亲子关系类型和明确排除的人物。
- 默认收录选定范围内全部成员与实际关系。配偶扩展只增加所选范围人物的直接伴侣，不无限扩展姻亲。
- 全谱中未关联人物单独成节；无法确定单一始祖的连通分支分别编号，默认使用确定性顺序。
- 起始人物及起始世数可配置。世代由选定关系推导；有冲突、自关系或环时生成校对提示，以引用边呈现，遍历必须终止，不能修改或删除原关系。
- 无亲子关系依据且未明确指定起始世数的人物标记“世代未定”，不因伴侣关系推定同世；同一分支内放在已知世代之后。
- 同一人物只有一份完整传记，在其他图页出现时引用本册编号。重名不合并。人物 UUID 是真实身份，本册编号是展示值；编号、页码可随新版范围和排版变化。
- 遍历、排序、编号和分页必须确定：相同资料快照和方案产生相同人物顺序、章节与页码。比较时间相同的记录以稳定 ID 排序。
- 预览列出收录人数、分支数、关系数、排除人数、页数、警告和排除原因；范围外亲属只作范围外引用，不泄露其被排除的详细资料。

## 4. 图片、引文与 PDF 附录

- 仅使用项目管理的附件 ID 和内容哈希，不在方案中保存用户原始路径，不从来源 URL 下载文件。
- 图片可选为封面、人物照片或史料插页，可设置说明。保持长宽比，不裁掉内容；按输出尺寸控制解码和像素预算。缺失图片必须列入校对报告，不能静默消失。
- 引用对应来源、原有页码/定位信息及摘录；来源目录去重。引用中的原书页码与本册页码明确区分。
- 已有关联来源但没有细化引文的记录仍列出来源名称；缺失定位信息时不打印空的“原资料定位”。
- PDF 附录显示项目内可用 PDF 的页数，支持如 `1-3,5` 的一基页码选择，保留用户选择的页面顺序，拒绝空选择、越界或非法区间。
- 每个选中原 PDF 页占一个附录页，适配本册纸张并保留页边距、原文件名及原页码说明；本册页码连续，目录和索引计入附录页数。
- 导入的 PDF 只呈现页面内容，不继承脚本、启动动作、外部文件操作或表单执行能力。加密、损坏、资源超限或不支持的 PDF 产生可操作的错误，不输出空白替代页。
- 用户可从方案中移除有问题的附件后重试。不存在自动跳过已选择史料的成功路径。

## 5. 纸张与预览

- 支持 A4、A3、ISO B5 和自定义纸张；单位毫米，方向、字号、页边距、装订边距可设置。现代默认正文 12 pt；传统默认 14 pt；图中文字最低 10 pt，用户可调大。
- 双面模式使用镜像内外边距，传统右侧装订对应调整。成品页序为自然阅读顺序，不自行制作印刷厂折手拼版。
- 内置可离线分发的中文字体并按需嵌入 PDF；优先矢量文字与关系线。生成前检查缺字并指明字符和相关条目；禁止以方框静默替代姓名。
- 预览显示最终生成 PDF，支持页码跳转、前后页、缩放和按需加载缩略图；不把单独的 HTML 模拟页面当作最终输出效果。
- 预览、保存使用同一份生成结果。方案修改、资料 revision 变化或任务失效后，提示重新生成，不把旧结果标作新版本。
- 文档包含可搜索文字、章节书签和可点击的内部页码链接；图像型原 PDF 页面不承诺自动 OCR。

## 6. 用户流程与界面

“编印族谱”置于项目管理子菜单，入口为项目概览中的管理工具卡片和项目管理二级导航。路由 `/project/:projectId/manage/publication`，旧路径 `/project/:projectId/publication` 重定向到新路径。沿用 ProjectLayout、AppSidebar、AppTopbar 和全局刷新，提供“返回项目管理”。路由懒加载，业务代码放在 `features/publication`。

流程：选用/新建方案 → 选择成品与范围 → 编辑章节、纸面和附件 → 生成与校对 → 检查 PDF → 保存。

桌面采用设置区和纸面预览区并列；手机以设置/预览切换呈现，所有选项均可操作。风格沿用现有有谱设计系统，预览中的真实纸张、页码和版心是界面重点，不增加营销装饰。

覆盖初次进入、项目无人、加载失败、未生成、生成中、取消中、生成失败、校对未通过、已生成、过期和保存成功/失败。生成有阶段与计数反馈，后台执行，允许取消、重试。连续点击不重复启动，离开页面或切换项目能释放任务。不能覆盖未确认的既有文件；取消文件选择不显示失败。

方案支持命名、新建、复制、保存、删除。删除仅删除编印方案，说明影响并确认，不删除人物、附件或已导出的 PDF。未保存的改动在离开时提示。

## 7. 数据与系统边界

业务选择、校验、稳定排序、世代推导、分页、PDF 生成与附件处理属于共享 Rust 核心 `ApplicationService` 或其下层。Vue 只通过 `BranchloomRepository` 读取业务数据和操作任务；Tauri 与 Web bridge 为薄适配。

方案保存为项目作用域的持久化设置，纳入项目备份、导入导出及同步时必须明确兼容策略；不能使旧客户端静默丢失方案。方案不含凭据、外部文件路径、预览缓存或成品 PDF。生成本身只读项目快照；保存方案不改写人物、关系和来源。

任务基于一致的项目 revision 与方案快照，在后台执行。使用任务 ID 隔离项目与生成结果，PDF 保存在受控临时目录中，取消、失败、过期及任务释放时清理。预览按页/字节范围读取，避免 JSON 数字数组传输整份大文件。保存成功前先完成生成，避免失败时留下被误认为完整成品的文件。

桌面通过原生保存对话框选择路径；Android 使用系统文件选择器的文档 URI，并复用现有文件交换适配。四个平台共用同一套生成逻辑和字体资源，不依赖系统安装浏览器、Word、打印驱动、网络字体或在线排版服务。

建议接口形态（内部应用接口，不直接等同于公共 CLI）：

```text
getPublicationPlans(projectId)
savePublicationPlan(projectId, plan, expectedRevision)
deletePublicationPlan(projectId, planId, expectedRevision)
startPublication(projectId, plan, expectedRevision) -> jobId
getPublicationStatus(projectId, jobId) -> state, progress, summary, issues
readPublicationRange(projectId, jobId, offset, length) -> bytes
savePublicationPdf(projectId, jobId, destination)
cancelPublication(projectId, jobId)
releasePublication(projectId, jobId)
```

公共 CLI 保持 contract version 3。实施时评估新增可选项目字段对 describe、输出和导入导出的影响；不绕过预览、etag、revision 或危险操作确认。不因有谱应用新增功能而顺带增加未讨论的 Word/SVG 或外部发布能力。

## 8. 验收

所有测试使用临时数据库和虚构资料，不读取默认应用数据目录。

### 功能与正确性

1. 三类成品均能生成、预览、保存并重新打开；传统版真实竖排且采用图传分节。
2. 全谱与分支范围准确，人物不因画布限制遗漏；重名、孤立节点、多伴侣、收养、继亲、监护、自关系和环均有回归覆盖。
3. 长姓名、长传记、空日期、模糊日期、简繁汉字和中西文混排不截断、不重叠、不虚构信息；缺字可定位。
4. 目录、人物编号、内部链接、接续页码和姓名索引与最终页数一致，包含多页 PDF 附录。
5. 验证图片比例、PDF 选页顺序、原页码、旋转页面、不同页面尺寸、损坏/加密文件和缺失附件。
6. 保存、复制、删除和重新打开方案可靠；revision 冲突不覆盖其他修改；备份与迁移不丢失方案。
7. 取消任务、重复生成、切换项目、生成失败和保存失败均不泄漏临时文件，不产生错误的成功提示。
8. 导出不修改人物、关系、来源或原附件；预览结果和保存字节一致。

### 规模与平台

- 使用固定种子的 10,000 人虚构项目测试宽分支、深世代、多分支及关联关系；统计完整收录和引用数量，记录页数、耗时、峰值内存和输出大小。
- 文字谱册、带图片/附录谱册、分幅挂图分别测量；不能只测试空白姓名列表后声称支持万人族谱。
- 每个平台验证字体嵌入、输出文字、页数、分页和文件保存；Android 额外验证系统文档 URI、后台生成时交互、取消和内存峰值。
- 性能结果须记录运行设备与测试负载。未能实际执行的平台验收明确标为未验证，不能以共享代码通过测试替代四平台实测。

### 自动化与人工检查

- 按影响运行 `pnpm typecheck`、`pnpm test:unit`、`pnpm test:cli`、`cargo test --workspace`、`pnpm test:e2e`，以及 Rust fmt/check/clippy。
- 新页面覆盖统一外壳、窄屏、键盘导航、焦点和无障碍标签。
- 对真实生成的虚构样张做 PDF 结构、文字提取、字体嵌入和页码验证；渲染关键页面逐页检查封面、世系跨页、长传记、传统标点、图片、附录和索引。
- 未完成的验收项不得描述为已交付。实现、测试和说明文档与本规格一致，不能用临时占位或禁用入口代替确认的能力。

## 9. 实施约定

- 共享核心采用 Krilla 0.8.2 输出 PDF 2.0，Hayro 只复制附录页面内容与资源；PNG/JPEG/WebP/GIF 图片由 image 解码。中文正文使用随应用分发的 Noto Serif CJK SC 2.003（OFL），按使用字符嵌入子集；不依赖系统中文字体。
- 传统标点使用对应的竖排字形，数字和拉丁字符逐字直立排列；ToUnicode 保留原字符，竖排文字附带 ActualText，便于支持该属性的阅读器搜索、复制。来源 PDF 的既有文字与字体资源保持原貌；扫描件不自动 OCR。
- 前端 PDF.js 及其 worker、CMap、标准字体和解码器随应用构建，预览通过核心分块读取（单次最多 1 MiB）。只绘制当前页及至多 7 张附近缩略图，完成渲染后释放页面解析缓存。
- 项目格式升级为 1.1.0、SQLite schema 6；可读 1.0.0，旧客户端明确拒绝新项目。方案字段保存在项目中，引用附件 ID；同步冲突按整个 publicationPlans 字段处理。公共 CLI contract 3 不变，不新增 PDF CLI 命令。
- 生成任务在单独工作线程使用不可变项目快照，应用内同一时间只运行一个任务，最多保留四份待释放任务。检测到 revision 变化即使结果失效并删除其临时 PDF，离开页面释放整个任务；取消在阶段、分页及 PDF 页面间检查，不承诺中断第三方库的单次封装调用。
- 自定义纸张边长 100～1200 mm，正文 8～40 pt，挂图 10～40 pt；单幅挂图边长上限 5.08 m。成品最多 20,000 页，超过时要求缩小范围或调整纸张，不悄悄压缩字号。
- 单个原附件最多 100 MiB；图片解码预算 64 MiB、最大边长 16,000 像素，排版图片按纸张长边的 300 dpi 像素需求等比缩小、上限 6,000 像素，不放大小图；保留的图片压缩数据与 PDF 原数据合计最多 128 MiB。图片和 PDF 资源预算不等于整个进程的内存上限。
- PDF 来源最多 10,000 页、200,000 个对象；页面内容解码后超过 32 MiB 拒绝。检查不能视作对所有恶意压缩文件的硬内存隔离，源文件解析仍在本地进程中执行。
- 长图注或过长原文件名若超出图版说明区，先完整分页呈现文字，随后图版标明前页说明或文件名；原 PDF 每个选页仍完整占一页，选页顺序不变。
- 图片先应用 EXIF 方向再排版；JPEG 保持 JPEG 编码（质量 90），其余支持的图片使用 PNG，以保留透明度，避免把照片统一转成 PNG 导致文件与内存大幅膨胀。重编码不携带原 EXIF 元数据。
- 桌面保存通过同目录临时文件及不可覆盖的落盘操作保护既有文件；Android 复用系统文档 URI 保存适配。Web 开发模式支持浏览器下载，预览分块读取，但下载时浏览器需汇集成品文件。
